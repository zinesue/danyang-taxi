# 운임·데이터 기준

## 운임의 확인 범위

단양군 공식 사이트에 게시된 [2023년 9월 5일 회의자료의 택시요금 변경 안내](https://www.danyang.go.kr/File/4d6251d8b767dbf5bebe7b8bdc004d54)는 2023년 8월 21일 시행 운임을 안내합니다. 검색 색인에서 확인한 단가는 다음과 같습니다. 원문 파일 직접 열기는 점검 시 사이트 방화벽에 차단되었습니다.

| 항목 | 적용한 설정 |
|---|---:|
| 기본거리 / 기본요금 | 1,350m / 4,000원 |
| 4km 미만 거리 단위 | 85m / 100원 |
| 4km 초과 거리 단위 | 80m / 100원 |
| 호출료 | 계산 엔진은 매 탑승 1,000원을 지원하나, 테스트 화면은 미포함 고정 |

해당 안내는 복합할증이 거리 단가에 이미 포함된 것으로 설명합니다. 별도 복합할증을 더하지 않습니다. 2026-11-07 개발 점검에서 이후 변경 고시와 미터기 동작을 확정하지 못했으므로 **최신 실차 미터와 동일한 운임이라고 보증하지 않습니다.** 공시 개정 시 `public/data/fare-config.json`을 수정하세요.

## 구현한 예산용 추정 규칙

선택한 도로 위치 사이의 이동거리 `d`(m)에 대해:

```text
이동 없음 (d ≤ 0.01m): 0원, 호출료 없음, 탑승 횟수 없음
near = max(0, min(d, 4000) - 1350)
far  = max(0, d - 4000)
거리 추가요금 = ceil(near / 85 + far / 80) × 100원
소계 = 기본요금 4000 + 거리 추가요금 + 선택 호출료
예산 확보 금액 = ceil(소계 × (1 + 여유율 / 100) / 100) × 100원
```

85m·80m 단위를 구간별로 누적한 후 한 번 올림합니다. 4km에 도달했다고 이전 주행 구간 전체를 80m 단위로 다시 계산하지 않습니다. 기본거리·요금 증가 경계에서는 부동소수점 오차를 보정합니다.

위 구간 전환·누적 단수 처리와 ‘부분 단위도 올림’은 **공식 자료에 없는 부분에 대한 명시적이고 보수적인 예산용 가정**입니다. 실제 미터기 펄스 처리의 재현으로 표현하지 않습니다. 향후 확인된 미터기 규칙으로 교체할 때 `fare.ts`, `fareThresholds`, 경계 테스트를 함께 갱신해야 합니다.

기본거리 이내 새 탑승마다 기본요금이 반복됩니다. 예를 들어 500m를 세 번 타면 여유율·호출료가 없을 때 12,000원입니다. 합산거리 1.5km의 1회 운임으로 계산하지 않습니다.

여유율은 교통 상황의 시간요금을 계산한 값이 아닙니다. 저속 시간요금, 심야할증, 통행료, 대기·택시 배차 여부는 제외되어 있습니다.

## 공간 데이터의 가정

원본 2D SHP의 실제 필드는 `RN`, `RDS_MAN_NO`, `RN_CD`, `ROA_CLS_SE`, `ROAD_BT`, `ROAD_LT`, `SIG_CD` 등입니다. 방향, 교량/터널, 층위, 접근제한 필드가 없어 원본으로 확인할 수 없는 속성을 생성하지 않았습니다.

- 그래프 `dir=0`: 양방향 가정. 엔진은 `1`(a→b), `-1`(b→a)도 지원합니다.
- 그래프 `record`는 원본 도로 행의 0부터 시작하는 인덱스입니다. 추후 원본과 대조할 수 있습니다.
- 기존 공유 꼭짓점(소수점 둘째 자리 미터로 정규화) 및 0.50m 이내 끝점 접촉을 공통 노드로 통합합니다. 가까운 끝점의 중복 분할을 단순 삭제하던 기존 누락을 수정했습니다.
- 끝점→선 중간 접촉은 대상 선을 분할합니다. 병합 묶음 내 원래 좌표 간 거리는 허용 거리+분할 오차 0.02m 이내로 제한합니다.
- 고속도로·자전거·등산 명칭이 포함된 도로의 1cm 초과 새 간격 접촉은 보류합니다. 기존 연결을 지우거나 해당 도로 전체의 차량 접근 여부를 단정하지는 않습니다.
- 원본은 유지하고 분석용 자료만 보정합니다. 1cm 초과 보정 후보는 `public/data/topology-repairs.json`에서 원본 행 번호와 좌표를 대조할 수 있습니다.
- 내부 교차점 전체를 `unary_union`으로 분할하지 않습니다. 입체교차를 무조건 평면교차로 만들지 않기 위한 선택입니다.
- 보정 후 남은 30개 연결 성분은 유지합니다. 큰 틈·내부 교차점은 실제 연결을 확인하기 전까지 추가 연결하지 않습니다.
- 도로 중앙선이 실제 택시 접근 가능 위치와 다를 수 있습니다. 도로 폭으로 통행 가능성을 추정하지 않습니다.
- OSM의 일방통행·접근제한을 SHP에 자동 매칭하지 않았습니다. 네트워크 보완에는 별도의 검증과 출처 기록이 필요합니다.
- 경로의 초록색 표시는 이 모델의 예산 충족을 의미하며 실차 통행의 보증이 아닙니다.

## 기초구간을 사용한 주소 추정

주소 검색에는 새 자료 중 **도로명 기초구간만** 사용합니다. 출입구의 건물 관리번호는 주소 번호가 아니므로 검색 키로 쓰지 않습니다. 기초구간과 기존 도로의 `SIG_CD + RDS_MAN_NO`를 결합해 도로명을 얻고, 입력 본번·부번을 홀수/짝수 기초번호와 정확히 대조합니다. 기초번호의 존재는 건물 주소의 존재를 보증하지 않습니다.

EPSG:5179에서 각 선 부분의 길이 중점을 구한 후 경위도로 변환합니다. 좌우 번호는 같은 도로 중점으로 표현하며 출입구나 차로 방향을 추정하지 않습니다. 복수 구간·분리 선형은 각각 별도 후보로 남깁니다. 구간은 대부분 약 20m이나 100m 초과 16개도 있어 검색 결과에 각 구간 길이를 표시합니다. 같은 원본 도로의 그래프 선분으로만 투영하고, 500m 이내 대응 도로가 없으면 연결을 거절합니다.

단양군 코드 43800만 검색하며 읍면 접두어는 입력 편의를 위해 제거합니다. 읍면별 주소의 실제 유효성, 건물·상호·지번·동호수는 조회하지 않습니다. 다른 시군 주소로 확장하거나 미일치 번호를 가장 가까운 번호로 대신하지 않습니다. 검색·후보·확정 방문 목록에 도로 위치의 추정임을 표시합니다.

## 정적 서비스

서비스 실행 중 브라우저가 서버에 보내는 경로 탐색 요청은 없습니다. 공개된 정적 파일과 OSM 배경 타일만 읽습니다. 저장소 하위 경로를 포함한 URL에서 앱·Worker·공간 데이터가 모두 상대 경로로 로드됩니다. 테스트 화면에서는 지도 표시 설정도 간소화해 고정된 배경지도를 사용합니다. 배경 타일 로딩에 실패해도 도로 분석은 별도로 동작합니다. 전체 사이트를 오프라인 설치하는 PWA 기능은 포함하지 않습니다.

## 고정된 테스트 조건

출발·복귀 위치는 소노길의 가장 긴 주 연결망 구간 중점입니다(경도 128.3625056, 위도 36.9774407). 특정 시설 출입구를 뜻하지 않습니다. 여유율 10%, 호출료 미포함, 예산 2만~16만 원(2만 원 간격)을 적용하며 설정 변경과 경로 내보내기는 제공하지 않습니다.
